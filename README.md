# osm-pbf-ingest

Reads OpenStreetMap `.osm.pbf` files for map and routing compilers, in two
passes:

1. **Pass 1** (`prepare_ingest_index_with_options`) builds a compact
   node-location store and the relation indexes, and can keep the tagged nodes
   a filter accepts.
2. **Pass 2** (`run_pass2_with_options`) hands nodes, ways and relations to
   your `Pass2Sink` as normalized batches, in file order. It can skip the node
   blobs and filter ways.

Both passes decode blocks on a pool of worker threads. On a file sorted by
type, each pass reads only the blobs that hold what it needs, found from the
file's block framing without decompressing anything.

## Example

```rust,no_run
use osm_pbf_ingest::{
    IngestBuildProfile, NodeBatch, Pass2Options, Pass2Sink, PrepareOptions, RelationBatch,
    WayBatch, prepare_ingest_index_with_options, run_pass2_with_options,
};
use std::path::Path;

#[derive(Default)]
struct Roads {
    ways: usize,
}

impl Pass2Sink for Roads {
    fn on_relation_batch(&mut self, _batch: RelationBatch) -> Result<(), String> {
        Ok(())
    }
    fn on_way_batch(&mut self, batch: WayBatch) -> Result<(), String> {
        self.ways += batch.ways.len();
        Ok(())
    }
    fn on_node_batch(&mut self, _batch: NodeBatch) -> Result<(), String> {
        Ok(())
    }
}

fn main() -> Result<(), String> {
    let pbf = Path::new("monaco.osm.pbf");
    let profile = IngestBuildProfile::DesktopFull;
    // Pass 1: node locations and relations, keeping the barrier nodes.
    let index = prepare_ingest_index_with_options(
        pbf,
        profile,
        Path::new("/tmp/ingest"),
        PrepareOptions::new().keep_nodes(|tags| tags.contains_key("barrier")),
        |_progress| {},
        || false, // return true to cancel
    )?;
    // Pass 2: the roads, without reading the node blobs again.
    let mut roads = Roads::default();
    run_pass2_with_options(
        pbf,
        profile,
        Pass2Options::new()
            .skip_nodes()
            .keep_ways(|tags| tags.contains_key("highway")),
        &mut roads,
        |_progress| {},
        || false,
    )?;
    println!("{} barriers, {} roads", index.tagged_nodes.len(), roads.ways);
    Ok(())
}
```

`blob_index::PbfBlobIndex::scan` reads just the file header and blob layout,
which is enough to read a PBF's header (bounds, feature flags) without
decompressing any data. See
`examples/` for more.

## Public API and buffa

`blob_index::read_blob_at` returns `blob_index::Blob`, a message generated by
[buffa](https://github.com/anthropics/buffa) from `proto/fileformat.proto`. A
buffa release that changes generated messages is therefore a breaking change
for this crate and needs a new minor release while the version is 0.x.

## The node store

Pass 1 keeps every node's location for pass 2's sinks to look up. On a file
sorted by ID, as Geofabrik extracts and the planet are, it packs the
locations in ID order, about 6 bytes per node: 146 MiB for the 24 million
nodes of the Małopolskie extract, which the sharded store of 0.2 held in
370 MiB. Each decode worker packs its own block's nodes, so nothing is sorted
or spilled. Inputs over 32 MiB (24 MiB on mobile) keep the store in a mapped
file under `temp_dir/node_store`, removed when the store is dropped. Files
not sorted by ID fall back to the sharded stores of 0.2.

`NodeLocationStore::cursor` looks up runs of nearby IDs, such as a way's
nodes, faster than `get`. For a caller that reads one area of a large file,
`NodeLocationStore::may_touch` rules out most ways outside it from the boxes
of the packed blocks, without looking their nodes up;
`PrepareOptions::keep_nodes_within` keeps only the tagged nodes inside it, and
`Pass2Options::keep_ways_where` drops the ways outside it on the decode
workers, before they get owned tags.

## Filtering by tags

`PrepareOptions::keep_nodes` (pass 1) and `Pass2Options::keep_ways` (pass 2)
take filters over `TagsRef`, the object's tags borrowed from the block, so an
object the filter rejects never gets owned `Tags`. `TagLookup` is implemented
by both `TagsRef` and `Tags`, so one helper can serve a filter and the code
that later reads the kept objects:

```rust
use osm_pbf_ingest::{Pass2Options, TagLookup};

fn is_road(tags: &(impl TagLookup + ?Sized)) -> bool {
    tags.has_tag("highway") || tags.tag("route") == Some("ferry")
}

let options = Pass2Options::new().skip_nodes().keep_ways(|tags| is_road(tags));
```

## How blocks are decoded

`PrimitiveBlock`s are decoded with buffa views over `proto/osmformat.proto`,
a copy of the OSM schema trimmed to the fields this crate reads: object
metadata (`Info`, `DenseInfo`) and changesets are skipped without being
parsed, and string tables are read in place.

A view decodes every packed array of every object into its own vector up
front, which for a block of ways takes longer than inflating it. Pass 2 reads
each way once, mostly to drop it, so it reads the groups of ways straight
from the wire instead, one value at a time as it uses them (`wire`,
`osm_block::PlainWay`); everything else, and ways not in the plain encoding
every writer produces (an unpacked or split list, a group mixing kinds),
still goes through a view, with the same results. Single-threaded, that
takes inflating and reading the way blocks of the Małopolskie extract from
1.25 s to 0.8 s, about half of it zlib. Pass 1 skips the groups of ways
undecoded, which matters on files not sorted by type.

The generated code is checked in under `src/proto/`; after editing
the schema, regenerate it with `scripts/gen-proto.sh` (needs `protoc`). Blob
framing and the file header use the same generated code, from
`proto/fileformat.proto` and `proto/osmformat.proto`. `osmpbfreader` is only a
dev-dependency: the tests check the decoder against it.

Version 0.x: the API may change between minor releases. It currently serves the
Meridian map and route compilers.
